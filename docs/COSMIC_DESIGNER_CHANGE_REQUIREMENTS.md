# CosmicDesigner 변경 개발 요건서

> 문서 목적: 반복적인 프로그램 테스트에서 발견되는 변경 요건을 사람과 Codex가 같은 의미로 이해하고, 추가·수정·삭제·구현·검증 상태를 일관되게 관리한다.

## 1. 문서 정보

| 항목 | 값 |
|---|---|
| 문서 ID | `CD-CRS` |
| 문서 버전 | `1.0` |
| 기준 프로그램 | `CosmicDesigner` |
| 기본 설계 단위 | `cm` |
| 최초 상태 | 제안됨 (`Proposed`) |
| 최종 갱신일 | 2026-10-01 |

## 2. 관리 규칙

### 2.1 요구사항 작성 형식

각 요구사항은 다음 필드를 사용한다.

| 필드 | 설명 |
|---|---|
| ID | 변경되지 않는 고유 식별자. 영역 접두사와 일련번호를 사용한다. |
| 제목 | 요구사항을 한 문장으로 요약한다. |
| 상태 | `Proposed`, `Approved`, `In Progress`, `Implemented`, `Verified`, `Deferred`, `Rejected` 중 하나를 사용한다. |
| 우선순위 | `Critical`, `High`, `Medium`, `Low` 중 하나를 사용한다. |
| 요구사항 | 사용자가 기대하는 동작과 제약을 기술한다. |
| 수용 기준 | 구현 완료를 판정할 수 있는 관찰·시험 조건을 기술한다. |
| 의존성 | 선행 요구사항이나 영향을 받는 기능을 기록한다. |
| 비고 | 설계 결정, 미확정 사항, 원문 해석을 기록한다. |

### 2.2 변경 원칙

1. 새 항목에는 기존 ID를 재사용하지 않고 다음 일련번호를 부여한다.
2. 내용 수정 시 사용자의 의도와 행위 결과를 유지하고 문서 하단 변경 이력에 기록한다.
3. 삭제된 요건의 ID는 재사용하지 않는다. 추적이 필요하면 상태를 `Rejected` 또는 `Deferred`로 변경하고 사유를 남긴다.
4. 구현 전에는 상태를 `Approved`로 변경한다. 구현 후에는 `Implemented`, 테스트 통과 후에는 `Verified`로 변경한다.
5. 수용 기준을 만족하지 못한 항목은 `Verified`로 표시하지 않는다.
6. 여러 항목에 공통으로 적용되는 정책은 중복 서술하지 않고 정책 ID를 의존성으로 참조한다.
7. 파일 포맷 변경, 기존 데이터 호환성 훼손 또는 사용자 데이터 마이그레이션은 명시적 승인 없이는 시행하지 않는다.

### 2.3 ID 접두사

| 접두사 | 영역 |
|---|---|
| `POL` | 개발 및 파일 포맷 정책 |
| `MENU` | Menu Bar |
| `VIEW` | 전역 보기 상태와 지속성 |
| `FLAT` | Flat Designer |
| `SECT` | Section Designer |
| `TEST` | 검증 및 회귀 테스트 |

## 3. 개발 및 파일 포맷 정책

### POL-001 — CDF 포맷 제안 및 승인 절차

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - 기능 추가를 기존 DXF 파일 포맷으로 온전히 처리할 수 없다면 새 파일 포맷 도입을 제안할 수 있다.
  - 새 포맷은 **Cosmic Design Format**으로 정의하고 확장자는 `.cdf`를 사용한다.
  - `.cdf` 도입과 프로그램 변경은 사용자 승인 후에만 수행한다.
  - 승인 전까지 DXF 호환 방식을 임의로 폐기하거나 `.cdf`를 기본 저장 형식으로 변경하지 않는다.
- 수용 기준:
  1. DXF로 표현할 수 없는 데이터와 그 근거가 제안서에 명시된다.
  2. DXF 유지, DXF와 CDF 병행, CDF 전환의 장단점 및 마이그레이션 영향이 제시된다.
  3. 사용자 승인 기록이 확인된 후에만 `.cdf` 읽기·쓰기 구현이 시작된다.
- 의존성: 없음
- 비고: **결정 게이트**에 해당하며 현재 `.cdf` 구현을 승인한 것은 아니다.

## 4. Menu Bar 및 전역 보기 상태

### MENU-001 — 최근 파일 메뉴

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - `File > Open` 다음에 `Recent` 캐스케이드 서브메뉴를 추가한다.
  - 최근에 연 파일을 최신순으로 최대 10개 표시한다.
  - 항목을 선택하면 일반 `Open`과 동일한 절차로 파일을 연다.
- 수용 기준:
  1. 열기에 성공한 파일만 최근 목록의 첫 위치에 추가된다.
  2. 같은 경로는 중복 표시하지 않고 최신 위치로 이동한다.
  3. 목록은 10개를 초과하지 않는다.
  4. 존재하지 않거나 접근할 수 없는 파일을 선택하면 오류를 알리고 해당 항목을 정리할 수 있다.
  5. 프로그램을 다시 실행해도 최근 목록이 유지된다.
- 의존성: `VIEW-002`

### MENU-002 — View 메뉴 구조

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - Menu Bar에 `View` 메뉴를 추가한다.
  - 다음 메뉴 구조를 제공한다.

```text
View
├─ Zoom
│  ├─ Zoom In
│  ├─ Zoom Out
│  └─ Fit to Window
├─ Ruler          [check]
├─ Grid           [check]
└─ Status Bar     [check]
```

- 수용 기준:
  1. `Zoom In`, `Zoom Out`, `Fit to Window`가 `Flat Designer`에 적용된다.
  2. `Ruler`, `Grid`, `Status Bar`는 체크형 메뉴이며 실제 표시 상태와 항상 일치한다.
- 의존성: `FLAT-003`, `FLAT-004`, `VIEW-001`

### VIEW-001 — 보기 상태의 전역 지속성

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - `Ruler`, `Grid`, `Status Bar`의 표시 여부를 현재 파일과 독립적인 프로그램 전역 설정으로 관리한다.
  - Registry 또는 동등한 지속성 저장소에 저장한다.
- 수용 기준:
  1. 설정 변경 직후 UI와 메뉴 체크 상태가 함께 갱신된다.
  2. 다른 파일을 열어도 설정이 유지된다.
  3. 프로그램 종료 후 다시 실행해도 설정이 복원된다.
  4. 설정이 없거나 손상된 경우 안전한 기본값으로 실행된다.
- 의존성: `MENU-002`

### VIEW-002 — 최근 파일 목록의 지속성

- 상태: `Proposed`
- 우선순위: `Medium`
- 요구사항: 최근 파일 경로와 순서를 프로그램 전역 지속성 저장소에 보관한다.
- 수용 기준:
  1. 프로그램 재실행 후 최대 10개의 경로와 순서가 복원된다.
  2. 경로 비교는 Windows 경로의 대소문자 차이로 중복을 만들지 않는다.
- 의존성: `MENU-001`

## 5. Flat Designer

### FLAT-001 — 기본 포인터 및 유휴 상태

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - Flat Designer에 진입할 때 기본 포인터는 Windows 기본 포인터이다.
  - 도구를 선택하지 않은 기본 상태에서는 포인터 이동만 가능하며 클릭이나 드래그가 임의의 생성·수정 작업을 시작하지 않는다.
- 수용 기준:
  1. Hole 도구나 객체 조작 대상이 없는 상태에서 포인터가 기본 모양이다.
  2. 빈 공간의 좌클릭·드래그가 설계 데이터를 변경하지 않는다.
- 의존성: 없음

### FLAT-002 — 중복 재료 크기 텍스트 제거

- 상태: `Proposed`
- 우선순위: `Low`
- 요구사항: Flat Designer 상단의 `Flat 300 × 300 cm` 형식 텍스트는 Material 속성과 중복되므로 제거한다.
- 수용 기준: Flat Designer 내부에는 해당 요약 문구가 표시되지 않고 Material 속성에서는 크기를 계속 확인할 수 있다.
- 의존성: 없음

### FLAT-003 — 오른쪽 버튼 Pan

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - 기본 상태에서 마우스 오른쪽 버튼을 누르고 있는 동안 포인터를 grabbing 형태로 변경한다.
  - 드래그 이동량에 따라 눈금자, 격자와 모든 설계 객체를 포함한 화면을 상하좌우로 이동한다.
  - 버튼을 놓으면 Pan을 종료하고 직전 포인터 상태로 복원한다.
- 수용 기준:
  1. 오른쪽 버튼 드래그 중 설계 데이터 좌표는 변경되지 않고 화면 변환값만 바뀐다.
  2. 버튼을 놓거나 캡처가 해제되면 Pan 상태가 남지 않는다.
  3. Pan 이후에도 선택, Hole 생성과 객체 편집 좌표가 화면 변환과 일치한다.
- 의존성: `FLAT-001`, `FLAT-004`

### FLAT-004 — 눈금자와 격자 표시

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - Flat Designer 상단에 눈금자와 격자 표시를 각각 On/Off 할 수 있는 버튼을 제공한다.
  - 메뉴의 `Ruler`, `Grid`와 동일한 상태를 공유한다.
  - 눈금자와 격자는 객체 위치를 센티미터 단위로 직관적으로 파악할 수 있게 표시한다.
- 수용 기준:
  1. 버튼과 메뉴 중 어느 쪽에서 변경해도 양쪽 상태가 동기화된다.
  2. 확대·축소 단계에 맞추어 읽기 좋은 눈금 간격이 자동 선택된다.
  3. Pan과 Zoom 중 눈금, 격자와 객체 좌표가 어긋나지 않는다.
- 의존성: `MENU-002`, `VIEW-001`

### FLAT-005 — 휠 및 메뉴 Zoom

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - 마우스 휠로 눈금자, 격자와 설계 객체 전체를 확대·축소한다.
  - `View > Zoom > Zoom In`, `Zoom Out`, `Fit to Window`에서도 같은 확대·축소 기능을 제공한다.
  - 휠 Zoom은 가능한 경우 포인터가 가리키는 설계 좌표를 화면상 같은 위치에 유지한다.
- 수용 기준:
  1. 확대와 축소에 상한·하한이 있어 화면이 무효 상태가 되지 않는다.
  2. `Fit to Window`는 전체 재료와 설계 객체가 Flat Designer 영역에 들어오게 한다.
  3. Zoom 이후 선택·배치·이동·Resize 좌표 계산이 정확하다.
- 의존성: `MENU-002`, `FLAT-003`, `FLAT-004`

### FLAT-006 — Hole 생성 모드와 포인터 좌표

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - Hole 버튼을 선택하면 천공 모드로 전환하고 포인터를 crosshair로 변경한다.
  - 이동 중 포인터 중심의 설계 좌표를 Status Bar에 실시간으로 표시한다.
  - 클릭하면 해당 위치에 Cut Object를 생성하고 즉시 선택 상태로 만든다.
  - 선택된 객체에는 편집 가능한 모서리 또는 제어점을 작은 원으로 표시한다.
- 수용 기준:
  1. 표시 좌표와 생성된 객체의 중심 좌표가 현재 Pan/Zoom 변환을 반영해 일치한다.
  2. 생성 작업은 Undo/Redo 대상이다.
  3. 생성 직후 Object Tree, Property Editor와 Flat Designer의 선택 상태가 일치한다.
  4. 모드 취소 시 기본 포인터와 유휴 상태로 돌아간다.
- 의존성: `MENU-002`, `FLAT-001`, `FLAT-005`

### FLAT-007 — 모서리 제어점을 이용한 2축 Resize

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - 선택 객체의 모서리 제어점 위에서 위치에 따라 `NW`, `NE`, `SW`, `SE` Resize 포인터를 표시한다.
  - 제어점을 좌클릭하여 드래그하면 객체의 폭과 높이를 동시에 변경한다.
  - 버튼을 놓으면 Resize를 종료하고 상황에 맞는 이전 포인터로 복원한다.
- 수용 기준:
  1. 반대쪽 기준점 또는 정의된 Anchor 정책에 따라 폭·높이가 연속적으로 갱신된다.
  2. 객체의 최소 크기와 재료 경계 정책을 준수한다.
  3. 한 번의 드래그 작업은 하나의 Undo/Redo 단위로 기록된다.
  4. Property Editor와 L 레이어 Geometry가 변경 결과와 동기화된다.
- 의존성: `FLAT-006`, `FLAT-010`

### FLAT-008 — 변 제어선을 이용한 단일 축 Resize

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - 객체의 제어점 사이 경계선 위에서 가로 변은 `NS Resize`, 세로 변은 `EW Resize` 포인터를 표시한다.
  - 선택되지 않은 객체의 경계선을 누른 경우 먼저 객체를 선택한다.
  - 드래그하면 해당 축의 높이 또는 폭만 변경한다.
  - 버튼을 놓으면 Resize를 종료하고 포인터를 복원한다.
- 수용 기준:
  1. 가로 경계 드래그는 높이만, 세로 경계 드래그는 폭만 변경한다.
  2. 한 번의 드래그 작업은 하나의 Undo/Redo 단위로 기록된다.
  3. Property Editor와 Geometry가 즉시 동기화된다.
- 의존성: `FLAT-006`, `FLAT-010`

### FLAT-009 — 객체 Move

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - 선택되지 않은 객체 위에 포인터를 올리면 Move 가능 포인터를 표시한다.
  - 선택된 객체에서는 Resize Hit Area가 아닌 객체 내부에 포인터가 있을 때 Move 포인터를 표시한다.
  - 좌클릭 드래그로 객체를 원하는 위치로 이동하고 버튼을 놓으면 이동 상태와 포인터를 복원한다.
- 수용 기준:
  1. 드래그 시작 시 객체가 선택되고 Object Tree 및 Property Editor와 동기화된다.
  2. 이동 중 객체 형상은 변하지 않고 위치 속성만 변경된다.
  3. 재료 경계 정책을 준수한다.
  4. 한 번의 드래그 작업은 하나의 Undo/Redo 단위로 기록된다.
- 의존성: `FLAT-006`, `FLAT-010`

### FLAT-010 — 모든 Hole 형상의 공통 조작

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - Rectangle뿐 아니라 Circle, Arc, Sector, Ellipse, Triangle, Diamond, Parallelogram, Pentagon, Hexagon, Polygon 등 모든 천공 형상에 PowerPoint 도형 조작과 유사한 Move 및 Resize 기능을 제공한다.
  - 형상별 Geometry 재생성 규칙을 유지하면서 공통 선택·Hit Test·Drag 처리 체계를 사용한다.
- 수용 기준:
  1. 지원하는 모든 Hole 형상에 `FLAT-007`, `FLAT-008`, `FLAT-009`가 적용된다.
  2. Resize 후 각 형상의 폐곡선과 고유 특성이 유지된다.
  3. 저장 후 다시 열어도 이동·크기 변경 결과가 보존된다.
- 의존성: `FLAT-007`, `FLAT-008`, `FLAT-009`

## 6. Section Designer

### SECT-001 — 치수 편집 TextBox 투명화

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - 거리 표시와 편집에 사용하는 TextBox의 외곽선과 불투명 배경을 제거하거나 투명하게 한다.
  - 치수선과 기준점이 TextBox 뒤에서도 식별 가능해야 한다.
  - 편집 가능성, 포커스와 입력 상태는 사용자가 인식할 수 있어야 한다.
- 수용 기준:
  1. 기본 표시 상태에서 TextBox 배경과 테두리가 치수선 및 도형을 가리지 않는다.
  2. 포커스를 받았을 때는 입력 중임을 알 수 있는 최소한의 시각 피드백을 제공한다.
  3. Flat Mode와 Bent Mode의 치수 편집 기능이 그대로 동작한다.
- 의존성: 없음

### SECT-002 — Section Designer 보기 상태의 파일별 저장

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항:
  - `Dimensions`, `Bent Mode`, 회전 버튼으로 정한 회전 각도를 저장한다.
  - 파일을 저장하고 다시 열었을 때 각 Section Designer의 상태를 복원한다.
  - W Section과 H Section의 상태를 각각 독립적으로 관리한다.
- 저장 대상:

| 영역 | Dimensions | Bent Mode | Rotation |
|---|---|---|---|
| W Section Designer | Boolean | Boolean | `0`, `90`, `180`, `270` |
| H Section Designer | Boolean | Boolean | `0`, `90`, `180`, `270` |

- 수용 기준:
  1. W/H의 각 상태 조합을 저장한 뒤 닫고 다시 열면 동일하게 복원된다.
  2. 새 문서는 정의된 기본값으로 시작한다.
  3. 상태 데이터가 없는 기존 파일은 오류 없이 기본값으로 열린다.
  4. 현재 DXF 메타데이터로 안전하게 보존할 수 없다면 `POL-001` 절차에 따라 CDF 도입을 제안하고 승인 전에는 임의 전환하지 않는다.
- 의존성: `POL-001`

## 7. 공통 상호작용 우선순위

포인터가 여러 대상과 겹칠 때 다음 순서로 동작을 결정한다.

1. 활성화된 Hole 생성 도구
2. 선택 객체의 모서리 Resize Handle
3. 선택 또는 Hover 객체의 경계 Resize 영역
4. 객체 내부 Move 영역
5. 오른쪽 버튼 Pan
6. 기본 유휴 상태

오른쪽 버튼 Pan은 좌클릭 기반 생성·선택·Move·Resize와 충돌하지 않아야 한다.

## 8. 공통 검증 요건

### TEST-001 — Undo/Redo 통합

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항: Hole 생성, Move, Resize와 관련 속성 변경은 Undo/Redo 대상이어야 한다.
- 수용 기준: 각 드래그 제스처가 중간 프레임 수와 관계없이 하나의 이력 항목으로 기록된다.

### TEST-002 — 좌표 변환 회귀 테스트

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항: Pan, Zoom, Fit 상태별로 화면 좌표와 센티미터 설계 좌표의 상호 변환을 자동 검증한다.
- 수용 기준: 생성, Hit Test, Move와 Resize가 동일한 좌표 변환을 사용하고 허용 오차 안에서 일치한다.

### TEST-003 — 저장 및 재열기 회귀 테스트

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항: 최근 파일, 전역 보기 설정, 파일별 Section 상태와 수정된 Hole Geometry의 지속성을 각각 검증한다.
- 수용 기준: 프로그램 전역 상태와 파일별 상태가 서로 섞이지 않고 명세대로 복원된다.

### TEST-004 — 기존 기능 회귀 테스트

- 상태: `Proposed`
- 우선순위: `High`
- 요구사항: 변경 후 DXF 열기·자동 Import·저장, Object Tree 선택, Property 편집, Delete, Undo/Redo, Section Designer와 3D Preview가 기존 동작을 유지하는지 검증한다.
- 수용 기준: 자동 검증 프로젝트와 관련 프로그램 빌드가 오류 없이 통과한다.

## 9. 미확정 설계 결정
