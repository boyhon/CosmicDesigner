# CR-001 CDF 파일 포맷 제안 및 승인 정책

## Status

Verified

## Source Document

- [COSMIC_DESIGNER_CHANGE_REQUIREMENTS.md](../../COSMIC_DESIGNER_CHANGE_REQUIREMENTS.md)
- Source requirement: `POL-001`

## Request

DXF로 안전하게 표현할 수 없는 기능이 필요할 때 `.cdf` 확장자의 **Cosmic Design Format**을 제안하고, 사용자 승인 후에만 구현하거나 기본 포맷 정책을 변경할 수 있는 절차를 확립한다.

## Background

CosmicDesigner 전용 상태가 증가하면 DXF 및 현재 메타데이터 방식의 표현 한계와 외부 호환성 문제가 발생할 수 있다. 그러나 새로운 포맷을 성급하게 도입하면 기존 DXF 워크플로와 데이터 호환성을 훼손할 수 있다.

## Current Behavior

CosmicDesigner는 센티미터 단위 DXF와 CosmicDesigner JSON 메타데이터를 사용한다. 일반 DXF Import와 기존 메타데이터 호환 경로가 존재하며 `.cdf` 읽기·쓰기는 구현되어 있지 않다.

## Required Behavior

- DXF로 표현할 수 없는 데이터와 기술적 근거를 먼저 문서화한다.
- DXF 유지, DXF/CDF 병행, CDF 전환 대안을 비교한다.
- 호환성, 마이그레이션, 외부 도구 영향과 복구 방법을 제시한다.
- 사용자 명시적 승인 전에는 `.cdf` 구현, 기본 저장 포맷 변경 또는 DXF 호환 경로 폐기를 하지 않는다.
- 실제 포맷 결정은 장기간 유지되는 구조적 결정이므로 별도 ADR 생성을 검토한다.

## Scope

- CosmicDesigner 파일 열기·저장 정책
- 직렬화 데이터 모델
- DXF 호환성과 마이그레이션
- 향후 `.cdf` 스키마 및 버전 정책

## Implementation Notes

이 CR은 현재 CDF 구현 승인이 아니라 **결정 게이트 등록**이다. 실제 포맷 설계가 필요해지면 이 CR을 구체화하거나 후속 구현 CR과 ADR을 연결한다. 승인 전에는 application logic을 변경하지 않는다.

## Acceptance Criteria

1. DXF로 표현할 수 없는 구체적 데이터와 재현 사례가 문서화된다.
2. 세 가지 포맷 운용 대안과 각각의 장단점이 제시된다.
3. 기존 DXF, CosmicDesigner 메타데이터, 백업 및 마이그레이션 영향이 분석된다.
4. 사용자 승인 기록과 관련 ADR 또는 후속 CR이 연결되기 전에는 CDF 구현이 시작되지 않는다.
