# CR-021 미저장 변경 사항 저장 확인

## Status

Implemented

## Source

2026-10-03 user request.

## Request

파일을 연 후 디자이너 작업으로 공작 명령이 변경되었을 때 New, 다른 파일 Open 또는 Exit 전에 현재 파일을 저장할지 묻는 다이얼로그를 표시한다.

## Background

현재 문서 변경 여부를 추적하지 않아 New/Open/Exit가 저장되지 않은 작업을 즉시 교체하거나 종료할 수 있었다.

## Current Behavior

사용자가 명시적으로 Save하지 않은 상태에서도 확인 없이 새 문서를 만들고 다른 파일을 열거나 프로그램을 닫는다.

## Required Behavior

- 문서 형상, 절곡, 컷, 치수와 파일별 Section view 상태 변경을 미저장 상태로 기록한다.
- New, Open, Recent 파일 열기, File Exit 및 창 닫기 전에 미저장 상태를 확인한다.
- 확인창은 저장, 저장하지 않음, 취소의 세 선택을 제공한다.
- 저장 선택 시 기존 Save 또는 Save As 흐름이 성공한 후에만 요청 작업을 계속한다.
- 저장하지 않음 선택 시 요청 작업을 계속한다.
- 취소, Save As 취소 또는 저장 실패 시 현재 문서와 창을 그대로 유지한다.
- Save 성공 및 새 파일 Open 성공 후 미저장 상태를 해제한다.

## Scope

- MainWindow document dirty-state lifecycle
- New/Open/Recent/Exit/window-close confirmation
- Save/Save As 성공 여부 전달
- Undo/Redo와 파일별 Section view 변경 추적

## Implementation Notes

문서 변경 이벤트와 Section view metadata 변경에서 공통 dirty state를 설정한다. 모든 파괴적 문서 전환은 하나의 `ConfirmSaveChanges` 경로를 사용하며 WPF `Closing` 이벤트에서도 취소할 수 있다.

## Acceptance Criteria

1. 변경 후 New를 실행하면 저장 확인창이 표시된다.
2. 변경 후 Open 또는 Recent를 실행하면 저장 확인창이 표시된다.
3. 변경 후 File Exit 또는 창 X 닫기를 실행하면 저장 확인창이 표시된다.
4. Yes와 성공한 Save 후 요청 작업이 계속된다.
5. No 선택 시 저장하지 않고 요청 작업이 계속된다.
6. Cancel 또는 Save As 취소/실패 시 현재 작업이 유지된다.
7. 변경이 없으면 확인창 없이 요청 작업이 실행된다.
8. 저장 성공 후에는 추가 변경 전까지 확인창이 표시되지 않는다.
9. 전체 자동 회귀 테스트가 통과한다.
